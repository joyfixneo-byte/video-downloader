# Журнал функций

Что в проекте **уже есть** и **как этим пользоваться**. Это не план (план —
в [ROADMAP.md](../ROADMAP.md)), а справочник по готовому: одна строка на
функцию, с точкой входа в коде и местом в интерфейсе.

Зачем: чтобы не делать второй раз то, что уже есть, и чтобы не оставалось
функций, которые сделаны, но непонятно как вызвать или вообще нигде не
применяются.

**Правила ведения — в [CLAUDE.md](../CLAUDE.md), раздел «Журнал функций».**
Коротко: перед новой функцией — поискать здесь похожее; после — добавить строку.

Синхронность журнала с кодом проверяется автоматически:

```
python backend/test_functions_journal.py
```

Проверка падает, если ручка есть в коде но не в журнале, если журнал
ссылается на удалённую ручку, или если ручка описана, но фронт её не
вызывает («сделано, но не применяется в системе»).

Колонка «Где в интерфейсе» обязана быть заполнена. Если у функции
намеренно нет UI — начните ячейку со слова `нет` и напишите почему.

## Скачивание видео

| Функция | Точка входа | Где в интерфейсе |
|---|---|---|
| Разбор ссылки: название, плейлист/одиночное видео | `POST /api/info` | Вкладка «Видео» → поле «Ссылка на видео» → кнопка «Проверить» |
| Постановка загрузки в очередь (качество: лучшее/1080/720/480/mp3), staging в SMB и публикация готового файла в библиотеку | `POST /api/download` | Вкладка «Видео» → селект «Качество» → кнопка «Скачать» |
| Прогресс задачи (проценты, скорость, ETA) | `GET /api/status/{job_id}` | Карточка в «Загрузки», опрашивается сама раз в секунду |
| Возврат карточек активных задач после перезагрузки страницы | `GET /api/jobs` | Автоматически при входе; карточки снова появляются в «Загрузки» |
| Остановка задачи | `POST /api/cancel/{job_id}` | «Загрузки» → «Остановить» |
| Удаление задачи и файла с сервера | `POST /api/delete/{job_id}` | «Загрузки» → «Удалить с сервера» |
| Выбор серий плейлиста галочками | `renderPick()` | Карточка разбора → «Выбрать все» / «Снять все» / чекбоксы в списке |

| Приём YouTube-ссылки в личном Telegram, постановка лучшего качества в SMB, статус, повторная доставка недоставленного результата, отмена и дедупликация по canonical video ID (`backend/telegram_bot.py`) | `POST /api/download`, `GET /api/status/{job_id}`, `POST /api/cancel/{job_id}`, `GET /api/library` | нет веб-интерфейса сайта — использовать личный Telegram-бот, отправить ссылку; для остановки нажать inline-кнопку «Остановить» |

## Единая библиотека SMB

| Функция | Точка входа | Где в интерфейсе |
|---|---|---|
| Список своих старых/прерванных задач и локальных legacy-задач, свободное место; общие готовые файлы из SMB добавляются тем же списком на фронте | `GET /api/files` | Карточка «Библиотека SMB» → «Обновить» (и автоматически при входе) |
| Изоляция рабочих задач и preview по постоянному INSTANCE_ID: только свой staging и локальный legacy, без ссылок и автоматического присвоения старого общего staging | `_job_dir()`, `_iter_job_dirs()`, `_checked_work_path()` | нет отдельной кнопки — применяется к списку, скачиванию, удалению, возобновлению и очистке задач; настройка INSTANCE_ID описана в README |
| Автовозобновление прерванных торрентов только своего инстанса и локальных legacy-задач | `_resume_interrupted_torrents()` | нет UI — один раз при запуске сервиса; задачи появляются в «Загрузки» |
| Отдача файла (целиком или одного файла раздачи через `?path=`), включая текущую SMB-публикацию | `GET /api/file/{job_id}` | «Загрузки» → «Скачать»; «Файлы в раздаче» → «Скачать» в строке |
| Просмотр в браузере: mp4 как есть, mkv — ремукс ffmpeg на лету (небраузерные кодеки HEVC/AC3/DTS перекодируются); `?a=` — номер звуковой дорожки, `?hls=1` — поток для Safari | `GET /api/play/{job_id}` | «Загрузки» → «Смотреть» (оверлей-плеер) |
| Оверлей-плеер со своим ползунком для потоков без длительности | `openPlayer()` | Открывается кнопкой «Смотреть» из любого списка |
| Выбор звуковой дорожки при просмотре (дубляжи в раздачах) — перезапуск потока с той же секунды | `audioLabel()` | Плеер → выпадашка «Звук» под ползунком (видна, если дорожек больше одной) |
| HLS-поток для Safari (iPhone/iPad/Mac): плейлист и сегменты запущенной сессии | `GET /api/hls/{key}/{name}` | нет отдельной кнопки — Safari получает этот адрес автоматически по кнопке «Смотреть», Chrome остаётся на mp4-потоке |
| Остановка HLS-сессии (гасит ffmpeg и чистит сегменты в /tmp) | `POST /api/hls/{key}/stop` | Плеер → «Закрыть», а также при перемотке и смене дорожки |
| Автоудаление старых рабочих файлов через 3 часа (свой staging и локальный `DOWNLOAD_DIR`, включая временные транскрибации; общую SMB-библиотеку не трогает) | `_cleanup_loop()` | нет UI — фоновый цикл; срок жизни legacy-файла виден в карточке |

## Торренты

| Функция | Точка входа | Где в интерфейсе |
|---|---|---|
| Поиск раздач по трекеру | `GET /api/torrent/search` | Вкладка «Торренты» → поле «Название раздачи…» → «Искать» |
| Поиск раздач по Rutracker (только на инстансе с доступом к сайту) | `GET /api/rutracker/search` | Вкладка «Торренты» → карточка «Rutracker» → поле «Название раздачи…» → «Искать» |
| Карточка Rutracker или плашка «здесь недоступно» — по факту доступа сервера к сайту | `applyRutracker()` | Вкладка «Торренты» → карточка «Rutracker» либо плашка с причиной и ссылкой «открыть сайт с VPN» |
| Список файлов раздачи до скачивания (только метаданные) | `POST /api/torrent/files` | Вкладка «Торренты» → «Скачать» у найденной раздачи или вставленный magnet |
| Запуск скачивания выбранных файлов раздачи | `POST /api/torrent` | Список файлов раздачи → «Скачать выбранное» |
| Живой статус по каждому файлу раздачи (готов / в библиотеке / был удалён из неё / качается / не выбран) | `GET /api/torrent/{job_id}/files` | Раскрывающаяся табличка «Файлы в раздаче», обновляется раз в 2 с |
| Удаление одного файла раздачи | `POST /api/torrent/{job_id}/delete-file` | «Файлы в раздаче» → «Удалить» в строке файла |
| Докачка пропущенных файлов раздачи — в том числе во время идущей загрузки (aria2 перезапускается с расширенным списком, прогресс качающегося файла не теряется) | `POST /api/torrent/{job_id}/add-files` | «Файлы в раздаче» → «Докачать» в строке невыбранного файла; «Скачать заново» — в строке файла, удалённого из библиотеки |
| Завершение раздачи только после успешного aria2, перепроверки хэша и проверки всех выбранных файлов; ошибки сохраняют данные для возобновления | `_run_torrent()`, `_torrent_ready_files()` | «Загрузки» → статус раздачи → «Продолжить» при ошибке |
| Публикация только выбранных готовых файлов с пофайловым сохранением карты и выбора; после ошибки повтор не скачивает уже опубликованное, метаданные и невыбранные куски остаются в staging | `_drain_torrent_to_library()`, `_publish_torrent_file()` | «Библиотека SMB» → карточка раздачи → «Файлы в раздаче»; «В библиотеку» для ручного повтора после остановки загрузки |
| Удаление раздачи целиком (метаданные; готовые файлы библиотеки остаются) | `POST /api/delete/{job_id}` | «Библиотека SMB» → «Удалить раздачу» на карточке раздачи |
| Возобновление раздачи (в т.ч. после краша сервиса) и перечитывание хэша | `POST /api/torrent/{job_id}/resume` | «Загрузки» → «Продолжить»; «Библиотека SMB» → «Возобновить» / «Перечитать хэш» |
| Пауза раздачи | `POST /api/torrent/{job_id}/pause` | «Загрузки» → «Пауза» |
| Сортировка таблички файлов раздачи (имя/размер/статус/№) | `addTorrentFilesToggle()` | «Файлы в раздаче» → клик по заголовку колонки, повторный — обратный порядок |
| Скрытие невыбранных файлов раздачи | `addTorrentFilesToggle()` | «Файлы в раздаче» → «Показать пропущенные (N)» |

## Библиотека (SMB-витрина для телевизора)

| Функция | Точка входа | Где в интерфейсе |
|---|---|---|
| Копирование legacy-файла из старой рабочей папки в SMB | `POST /api/library/add` | «Библиотека SMB» → «В библиотеку» у legacy-файла |
| Атомарная публикация без перезаписи между VM; при совпадении имени сохраняются оба файла (включая одинаковые), при ошибке исходник остаётся | `_publish_to_share()`, `_rename_no_replace()` | «Библиотека SMB» → «В библиотеку» у legacy-файла; автоматически после скачивания видео или торрента |
| Список готовых файлов в SMB с именем и ID родительской торрент-задачи для группировки файлов | `GET /api/library` | Карточка «Библиотека SMB» → «Обновить» (общий список с задачами) |
| Скачивание файла из SMB | `GET /api/library/file` | «Библиотека SMB» → «Скачать»; «Файлы в раздаче» → «Скачать» у файла со статусом «в библиотеке» |
| Просмотр файла из SMB в браузере | `GET /api/library/play` | «Библиотека SMB» → «Смотреть»; «Файлы в раздаче» → «Смотреть» у файла со статусом «в библиотеке» |
| Удаление файла из SMB (навсегда) | `POST /api/library/delete` | «Библиотека SMB» → «Удалить» |
| Проверка SMB и понятная ошибка при незаданной/непригодной папке | `_require_library()` | При нажатии «Скачать» или «Скачать выбранное» показывается текст ошибки |

## Интерфейс и доступ

| Функция | Точка входа | Где в интерфейсе |
|---|---|---|
| Состояние инстанса: нужен ли пароль, доступен ли rutracker, версия yt-dlp, занят ли сервер | `GET /api/config` | Автоматически при загрузке страницы; решает, показывать ли карточку пароля, раздел rutracker и строку про yt-dlp внизу |
| Ночное автообновление yt-dlp с отложенным перезапуском, если идёт загрузка | `deploy/ytdlp-update.sh` | нет UI — systemd-таймер в 04:00; что он сделал и когда, видно строкой внизу страницы |
| Самопроверка сайта раз в минуту с перезапуском приложения или frp-туннеля | `deploy/watchdog.sh` | нет UI — systemd-таймер раз в минуту; что он делал, видно в `journalctl -u video-downloader-watchdog` |
| Строка «какая версия yt-dlp работает и ждёт ли она перезапуска» | `applyYtdlp()` | Самый низ страницы: «yt-dlp 2026.8.19 · проверено 25 авг, 04:12» |
| Вход по паролю, пароль хранится в браузере | `savePw()` | Карточка «Пароль доступа» → поле → «Войти» |
| Переключатель темы: авто (как в системе) → светлая → тёмная | `cycleTheme()` | Шапка страницы → кнопка «Тема: …»; выбор переживает перезагрузку |
| Вкладки «Видео» / «Торренты» | `showTab()` | Переключатель под заголовком страницы |
| Мини-игра «Тетрис» как экран ожидания | `GAME` | Карточка «Тетрис» → «Играть», кнопки `←` `↻` `↓` `→`, клавиатура, клавиша P — пауза |
| Общий рекорд тетриса (один на всех, хранится на сервере) | `GET /api/tetris/best` | Карточка «Тетрис» → строка «Рекорд» |
| Отправка нового личного рекорда на сервер | `POST /api/tetris/best` | Автоматически, когда счёт в тетрисе побил прежний рекорд |
