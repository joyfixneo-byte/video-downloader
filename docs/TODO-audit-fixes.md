## Границы

Реальные VM не обновляются автоматически. Живые проверки CIFS/aria2/YouTube
и Telegram на VM выполняются пользователем после обновления обоих инстансов.
Посторонние изменения ROADMAP.md, AGENTS.md и пользовательские вложения
не включаются в коммит.

## Результаты

1. Публикация использует атомарное переименование без перезаписи (Windows
   rename / Linux renameat2 RENAME_NOREPLACE). Коллизии получают суффикс;
   legacy-копии используют уникальный временный файл. При отказе исходник
   сохраняется. Проверено: 15 регрессионных тестов, журнал функций, diff.
2. Staging и preview изолированы по INSTANCE_ID (по умолчанию hostname).
   Обход, очистка и все операции задач используют свой namespace; локальные
   legacy-задачи и очистка транскрибаций сохранены. Старый общий staging
   не присваивается автоматически; переход описан в README. Проверено:
   29 тестов изоляции + 15 публикации, журнал и diff.
3. Успех торрента требует code=0, recheck и готовности выбранного набора.
   Ошибки подготовки/публикации оставляют задачу для повтора. Карта и выбор
   обновляются по каждому файлу; ручная публикация использует тот же путь.
   Проверено: 24 completion-теста (включая add-files на границе завершения),
   предыдущие проверки публикации/изоляции, журнал и diff. Аварийный краш
   между rename и записью карты остаётся ограничением; обычный отказ записи
   карты откатывает rename.
4. Плейлисты стартуют и по HTTP; карточка задачи остаётся одна при опросе /
   обновлении; API списка SMB сообщает ID родительского торрента, и файлы
   группируются с карточкой. Проверено Chromium по HTTP с mock API и API-тестом.
5. Результат терминальной задачи сохраняется в SQLite outbox до отправки.
   Worker повторяет недоставленное сообщение после ошибки и перезапуска;
   старая база дополняется без повторной отправки прежних результатов.
   Проверено offline с принудительным первым отказом Telegram и повторным
   успешным send; повторная загрузка не создаётся.
