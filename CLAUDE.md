# Инструкции для Claude по этому репозиторию

## Git: коммит и пуш автоматически

После завершения правок (код рабочий, самопроверки/тесты пройдены) —
коммить и пушь в `origin/main` **без запроса подтверждения**, если явно не
попросили иначе. Не нужно спрашивать "запушить?" каждый раз.

- Коммить только те файлы, которые сам изменил в рамках текущей задачи —
  не подмешивай посторонние незакоммиченные изменения (чужую работу в
  процессе, черновики, скриншоты и т.п. в рабочей копии).
- Если есть посторонние uncommitted-изменения, не относящиеся к задаче —
  оставь их как есть, застейджи и закоммить только свои файлы.
- Обычные (не деструктивные) команды — `git add <файлы>`, `git commit`,
  `git push origin main` — не требуют подтверждения в этом репозитории.
- Деструктивные операции (force-push, reset --hard, перезапись чужих
  коммитов, удаление веток) по-прежнему требуют явного подтверждения — это
  правило их не отменяет.
- После пуша на VM код нужно подтягивать вручную (`git pull` +
  `systemctl restart`) — эти команды на сервере выполняет пользователь сам
  (см. память `ssh-access-policy`), не автоматизируй их.

## Деплой: два живых инстанса одного кода

В проде одновременно крутятся **два инстанса этого репозитория** на разных
VM: `apps-vpn` (порт 8000, egress через VPN — нужен для YouTube и т.п.) и
`apps` (порт 8002, прямой egress без VPN — быстрее для торрентов, не
блокируется некоторыми сайтами). Это один и тот же код на обеих машинах,
не форк и не отдельная ветка — различие только в инфраструктуре
(VPN/порт/frp-туннель), не в приложении.

- Обычные правки в `backend/app.py`/`backend/static/index.html` не нужно
  писать «под конкретный инстанс» — один коммит в `main` закрывает оба
  сайта одинаково, если явно не попросили разное поведение в зависимости
  от VPN.
- Пользователь обновляет **оба** сервера вручную и по отдельности после
  пуша (`vdup` на каждой VM) — не предполагай, что после пуша сайты уже
  обновились, и не пытайся автоматизировать сам апдейт (см. выше).
