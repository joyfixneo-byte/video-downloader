## ✅ Сделано

### Скачивание (ядро)
- yt-dlp + ffmpeg, бэкенд FastAPI, фронтенд — один `backend/static/index.html`.
- Плейлисты → выбор серий галочками; качество (лучшее/1080/720/480/mp3).
- Прогресс в реальном времени; мини-игра «Тетрис» как экран загрузки.
- Автоудаление файлов через 3 часа; размер файла; список файлов на сервере.
- Остановка и удаление задач; необязательный пароль на вход.
- Фикс тяжёлых видео: список «на сервере» и выдача `/api/file` теперь читают
  готовый файл с диска и **игнорируют недокачанные** (`.part`/фрагменты), а
  активные задачи скрыты из списка — размер больше не «прыгает», файл не
  скачивается битым («чёрный экран с кодом»), и его можно забрать даже после
  перезапуска сервиса (`vdup`). Ссылки на файл — с атрибутом `download`.

### Транскрибация видео в текст
- Сначала готовые субтитры через yt-dlp (мгновенно, **оригинальный язык** —
  приоритет `info["language"]`, затем ru/en/любой), одним запросом.
- Если субтитров нет — локальный **Whisper** (faster-whisper, CPU, бесплатно).
- Лёгкий аудио-формат (`bestaudio/worstaudio/worst`) — не качаем весь видеофайл.
- Два режима Whisper: **быстрый** (`base`, `beam_size=1`) и **точный**
  (`WHISPER_MODEL_ACCURATE`, по умолч. `small`, `beam_size=5` +
  `condition_on_previous_text` + мягкий VAD) — точнее на русском/плохом звуке.
- **Субтитры с таймкодами**: и готовые (парсинг VTT в сегменты `start/end/text`,
  схлопывание дублей авто-субтитров), и Whisper возвращают сегменты со временем.
- Кнопка **«🎙 Свои субтитры»** — распознать своей моделью (точный режим),
  игнорируя встроенные авто-субтитры (`force_whisper`); из готовой задачи со
  встроенными есть кнопка «Сделать свои субтитры».
- **Скачивание в файл**: `.srt` (с таймкодами) и `.txt` (сплошной текст),
  генерируются на фронте из сегментов (Blob, BOM); переключатель показа таймкодов.
- Понятный статус по стадиям («Скачиваю аудио…» → «Загружаю модель…» →
  «Распознаю NN%») + счётчик времени; кнопка «Остановить». Кнопка «Копировать».

### Безопасность (перед выводом в интернет)
- **Пароль `DOWNLOADER_PASSWORD`** — основная защита (включён на проде).
- SSRF-guard: только http/https на публичные адреса (блок localhost, приватных
  сетей, облачных метаданных) на `/info`, `/download`, `/transcribe`.
- Потолок одновременных задач (`JOB_CEILING`/`TJOB_CEILING`) → 429 при флуде.
- Whisper сериализован семафором (`MAX_ACTIVE_TRANSCRIBE`), лимит длины ролика
  (`WHISPER_MAX_MINUTES`); необязательный лимит размера файла (`DOWNLOAD_MAX_GB`).

### Интерфейс
- Редизайн в стиле клейморфизм: приглушённый градиент (teal→персик),
  коралловый акцент, маджента-свечение на фокусе, шрифты Space Grotesk + Inter.
- Фикс автозума на iPhone Safari: поля ввода ≥16px + `maximum-scale=1`
  (страница больше не зумится и не «ездит» при тапе на поле ссылки).
- **Зум полностью отключён**: `user-scalable=no` + `touch-action:manipulation`
  + ручное глушение пинча и двойного тапа JS (iOS игнорит user-scalable) —
  случайный промах по кнопке в тетрисе больше не зумит и не ломает игру.
- Тетрис: рекорд хранится в localStorage; превью следующей фигуры;
  кнопки «Заново» и «Пауза» рядом (не нажать случайно при игре).
  Игра доступна **всегда** (отдельная карточка), а не только при загрузке;
  пауза с оверлеем «ПАУЗА», возобновление, клавиша P.

### Инфраструктура / деплой
- Работает на **VM-apps-vpn** (egress через VPN → YouTube доступен).
- Виден в интернете: `http://91.186.220.103:8000`
  (Интернет → VPS nginx :8000 → frps → frp-туннель → VM-apps-vpn :8000).
- Обновление одной командой: **`vdup`** (алиас → `deploy/update.sh`).
  Делает `git pull` с HTTP/1.1, автоповтором и таймаутом (VPN то рвёт, то
  подвешивает соединение с GitHub) и перезапускает сервис только если менялось
  что-то кроме `backend/static/`. `vdup --no-restart` — только pull.

## 🚧 Торренты — Фаза 1: поиск + скачивание ✅ (код готов, нужна проверка на VM)

Цель фазы: нашёл раздачу (или вставил magnet) → **aria2 качает её на сервер**,
файл появляется в общем списке и отдаётся теми же ручками, что и yt-dlp-загрузки.
Просмотр — после докачки (стриминг во время загрузки — Фаза 2 ниже).

Сделано в коде (`backend/app.py` + `static/index.html`):
- **Движок:** `aria2c` как subprocess в `DOWNLOAD_DIR/<job_id>/`, `--seed-time=0`
  (не раздаёт после докачки). Прогресс парсится в те же поля `JOBS`
  (percent/speed/eta/total), поэтому фронтовый `poll()`, `/api/status`,
  `/api/files`, `/api/file`, `/api/cancel`, `/api/delete` и автоочистка
  работают для торрентов **без изменений** (переиспользование, не дубли).
- **Поиск:** скрейпер 1337x на stdlib (`GET /api/torrent/search?q=`), magnet
  берётся лениво при добавлении. Ручной ввод magnet — запасной путь.
- **Добавление:** `POST /api/torrent {magnet|detail}`, валидация magnet-схемы,
  тот же потолок задач `JOB_CEILING`/429.
- **UI:** карточка «🧲 Торренты» (поиск + вставка magnet), результаты с
  сидами/размером, кнопка «Скачать» кладёт задачу в общий список загрузок.

⚠️ **Требуется ручная проверка на VM (human-in-the-loop):**
1. Поставить движок: **`apt install aria2`** на VM-apps-vpn.
2. Проверить, что **поиск реально что-то находит** через VPN (1337x может быть
   за Cloudflare / сменить вёрстку → тогда 502, вставляем magnet вручную;
   зеркало меняется через env `TRACKER_BASE`).
3. Проверить **связность aria2 через VPN** на легальной раздаче (Ubuntu ISO):
   пиры/DHT/трекеры должны быть доступны через туннель, файл докачивается.
4. Нет жёсткого лимита размера торрента (у yt-dlp есть `DOWNLOAD_MAX_GB`) —
   следить за диском; лимит — в бэклоге.

### Дополнение: выбор файлов + без автоудаления ✅ (код готов, нужна проверка на VM)

- **Автоочистка:** папка торрент-задачи помечается файлом `.torrent_job` —
  `_cleanup_loop` такие папки больше не трогает вообще, удаление только
  вручную кнопкой «Удалить». Маркер на диске (не в `JOBS`), переживает
  рестарт сервиса.
- **Выбор файлов до скачивания:** `POST /api/torrent/files {magnet|detail}` —
  aria2 качает только метаданные (`--bt-metadata-only`, секунды), свой
  мини-декодер bencode (без новой зависимости) достаёт список файлов
  (имя/размер), фронт показывает чекбоксы (переиспользован паттерн выбора
  серий плейлиста). `POST /api/torrent {token, files}` качает выбранное
  через `--select-file`. Если метаданные не получить (нет пиров) — запасной
  путь «Скачать всё как есть» (старое поведение, без выбора).
- **Просмотр скачанных файлов:** `GET /api/torrent/{job_id}/files` сканирует
  папку задачи с диска (переживает рестарт), фронт рисует раскрывающуюся
  табличку (имя/размер/ссылка) через нативный `<details>`; `/api/file`
  принимает `?path=` для скачивания конкретного файла раздачи.

⚠️ **Требуется ручная проверка на VM:** реальный `--bt-metadata-only` фетч
метаданных и `--select-file` через VPN/живые пиры — здесь не воспроизвести,
только модульно протестировано (bencode-парсинг, HTTP-эндпоинты с
подменённым aria2, path traversal, автоочистка) без сети.

## 🚧 Фаза 2 — просмотр видео во время загрузки (стриминг)

Цель: **смотришь видео в браузере, пока оно качается**.
1. **Sequential download** — aria2 для BT его толком не умеет; вероятно нужен
   `libtorrent` (python-биндинги) с последовательным режимом.
2. **Стриминг в браузер:** отдача файла с HTTP Range, плеер `<video>` (играет по
   мере докачки первых кусков).
3. **Кодеки:** mp4/H.264 играет нативно; для mkv — опционально ремукс через ffmpeg.
4. **Сеть/безопасность:** уже под тем же паролем; юридическая оговорка (в UI есть).
